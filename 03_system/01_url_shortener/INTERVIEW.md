### 1. 진행 방식

* 본인이 만든 애플리케이션을 직접 시연합니다.
* 약 5분간 시연·발표 후, 약 분간 기술 질의응답을 진행합니다.
* 사용 언어나 프레임워크에는 제한이 없습니다.
* 개인 노트북을 가져와 실행 화면과 소스 코드를 함께 보여주는 방식이 권장됩니다. 

발표에서는 서비스의 필요성이나 기획 배경을 길게 설명하기보다 다음 내용을 보여주는 것이 중요합니다.

1. 자신이 구현한 기능
2. 해당 기능이 실제로 작동하는 모습
3. 구현하면서 가장 중점을 둔 부분
4. 그 부분이 코드에서 어떻게 구현됐는지

### 2. 평가 기준

가장 먼저 보는 것은 기술력입니다. 기술 이름을 많이 나열하는 것보다, 해당 기술을 사용해 어떤 문제를 해결했고 무엇을 구현했는지를 평가합니다. 

신입 지원자에 대해서는 다음 두 요소를 각각 절반 정도 평가한다고 설명했습니다.

* 현재 보유한 기술 역량
* 향후 발전 가능성 

프로젝트 경험을 여러 개 나열하는 방식은 크게 평가받지 못합니다. 한 프로젝트에서 어떤 문제를 만났고, 어떻게 판단했으며, 그 과정에서 무엇을 얻었는지를 논리적으로 설명하는 능력이 중요합니다. 

실제 합격자는 공간정보 경로 추천 프로젝트에서 다익스트라와 A* 알고리즘을 어떻게 구현했는지, 구현 과정에서 어떤 고민을 했는지를 구체적으로 설명한 점이 좋은 반응을 얻었다고 밝혔습니다. 

### 3. 요구되는 기술 범위

기본 역량은 웹 풀스택 개발입니다. 공공기관 프로젝트가 많아 전자정부프레임워크 기반 웹 시스템 개발 역량을 중요하게 봅니다.

* Java 및 전자정부프레임워크 기반 백엔드
* JavaScript 기반 프론트엔드
* 데이터베이스와 웹 시스템 연동
* 시스템 전체 흐름을 이해하고 고객 요구에 대응할 수 있는 역량

JavaScript는 주로 프론트엔드 개발 역량을 의미합니다. Node.js나 React 프로젝트도 있지만, 주력은 전자정부프레임워크 기반 시스템이라고 설명했습니다. 

웹 풀스택 외에는 다음 기술을 추가 강점으로 제시할 수 있습니다.

* Python
* C#
* Unity
* Unreal Engine
* 외부 API 연동
* 데이터 수집 및 처리
* AI, LLM, 컴퓨터 비전

면접관은 약 20년 경력의 개발자들이며, 프로젝트 설명과 코드만으로 실제 기술 수준을 빠르게 파악한다고 언급했습니다. 

### 4. AI 활용 경험 평가

AI나 LLM 경험 자체는 강점이 될 수 있지만, 생성된 코드를 가져와 실행한 수준은 본인의 개발 경험으로 인정받기 어렵습니다.

AI가 작성한 코드라도 다음 내용을 설명할 수 있어야 합니다.

* 코드가 어떻게 동작하는지
* 문제가 발생하면 어느 부분을 확인해야 하는지
* 기존 시스템과 충돌하는 원인이 무엇인지
* 필요하면 직접 다시 구현할 수 있는지

공공기관 시스템은 소스 코드가 대외비인 경우가 많아, 장애 발생 시 전체 코드를 AI에 전달해 해결할 수 없습니다. 따라서 AI 활용 능력과 함께 기본 개발 역량과 코드 이해도를 확인합니다. 

LLM이나 컴퓨터 비전 구축 경험도 내부 구조와 소스 코드를 충분히 이해하고 있어야 유효한 기술 경험으로 평가됩니다. 

### 5. PPT 사용

PPT는 금지되지 않습니다. 다만 디자인에 시간을 들일 필요는 없으며, 아키텍처나 구현 구조처럼 실행 화면과 코드만으로 설명하기 어려운 내용을 보여주는 보조 자료로 사용하는 것이 적절합니다. 

핵심은 **작동하는 기능을 시연하고, 그 기능의 구현 판단과 코드를 연결해서 설명하는 것**입니다. 예상 질문도 기술 선택 이유, 본인 구현 범위, 문제 해결 과정, 코드 동작 원리, 대안과 장단점에 집중될 가능성이 높습니다.
