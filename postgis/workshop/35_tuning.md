# 35. PostgreSQL 기본 튜닝 (Basic PostgreSQL Tuning)

> 공식 원문: [<https://postgis.net/workshops/postgis-intro/tuning.html>](https://postgis.net/workshops/postgis-intro/tuning.html)\
> 공식 소스의 본문·표·SQL·이미지를 현재 페이지 순서대로 반영했습니다.

PostgreSQL은 리소스가 매우 적은 환경과 다양한 다른 애플리케이션과 공유되는 환경에서 효율적으로 실행할 수 있는 매우 다재다능한 데이터베이스 시스템입니다. 다양한 환경에서 제대로 실행되도록 하기 위해 기본 구성은 매우 보수적이며 고성능 프로덕션 데이터베이스에는 적합하지 않습니다. 지리공간 데이터베이스의 사용 패턴이 다르고 데이터가 비지리공간 데이터베이스보다 더 적고 훨씬 큰 레코드로 구성되는 경향이 있다는 사실을 추가하면 기본 구성이 우리 목적에 완전히 적합하지 않다는 것을 알 수 있습니다.

이러한 모든 구성 매개변수는 <span class="title-ref">postgresql.conf</span> 데이터베이스 구성 파일에서 편집할 수 있습니다. 이것은 일반 텍스트 파일이며 텍스트 편집기를 사용하여 편집할 수 있습니다. 서버를 다시 시작할 때까지 변경 사항이 적용되지 않습니다.

이 섹션에서는 보다 생산 준비가 완료된 지리공간 데이터베이스에 맞게 조정할 수 있는 일부 구성 매개변수에 대해 설명합니다.

> [!NOTE]
> 이 값은 권장사항일 뿐입니다. 각 환경은 다르므로 최적의 구성을 결정하려면 테스트가 필요합니다. 하지만 이 섹션에서는 좋은 시작을 도와줄 것입니다.

## shared_buffers

데이터베이스 서버가 공유 메모리 버퍼에 사용하는 메모리 양을 설정합니다. 이름에서 알 수 있듯이 백엔드 프로세스 간에 공유됩니다. 기본값은 일반적으로 프로덕션 데이터베이스에 적합하지 않습니다.

> *기본값*: 일반적으로 32MB
>
> *권장값*: 데이터베이스 메모리의 약 75%, 최대 약 2GB

## effective_cache_size

PostgreSQL이 `shared_buffers`용으로 설정한 메모리 외에도 쿼리 플래너는 운영 체제가 가상 파일 시스템의 일부로 캐시한 디스크 블록 수도 고려합니다. 메모리 용량이 큰 시스템의 경우 이는 상당히 클 수 있습니다. `effective_cache_size`는 대략 머신의 메모리 양에서 `shared_buffers`를 뺀 값, `work_mem`에 예상 연결 수를 곱한 값, 머신에서 실행 중인 다른 프로세스에 필요한 메모리 양을 뺀 값, 기타 임의 운영 체제 요구 사항에 필요한 약 1GB를 뺀 값입니다. 데이터베이스는 추가 캐시를 직접 **use**하지 않지만 운영 체제가 대략 그만큼의 메모리에 파일 시스템 데이터를 캐시했다고 예상하여 계획을 계산합니다.

> *기본값*: 일반적으로 4GB
>
> *권장 값*: 일반적인 작동 조건에서 예상되는 "여유" 메모리 양

## work_mem

데이터베이스가 온디스크 파일로 전환되기 전에 내부 정렬 작업, 인덱싱 작업 및 해시 테이블이 소비할 수 있는 메모리 양을 정의합니다. 이 값은 각 작업에 사용 가능한 메모리를 정의합니다. 복잡한 쿼리에는 여러 정렬 또는 해시 작업이 병렬로 실행될 수 있으며 연결된 각 세션이 쿼리를 실행할 수 있습니다.

따라서 이 값을 늘리기 전에 연결 수와 예상 쿼리의 복잡성을 고려해야 합니다. **benefit**의 장점은 디스크 쓰기 없이 ORDER BY, DISTINCT 절, 병합 및 해시 조인, 해시 기반 집계, 해시 기반 하위 쿼리 처리 등 더 많은 작업을 처리할 수 있다는 점입니다. 증가하는 **cost**는 **연결당** 사용되는 메모리이며, 이는 연결의 생산 수준에 따라 상당히 높을 수 있습니다.

> *기본값*: 1MB
>
> *권장값*: 32MB

## maintenance_work_mem

진공 청소, 인덱스 및 외래 키 생성을 포함하여 유지 관리 작업에 사용되는 메모리 양을 정의합니다. 이러한 작업은 그다지 일반적이지 않으므로 값이 높을수록 가끔 발생하는 비용만 발생하고 유지 관리 활동 속도가 크게 향상될 수 있습니다. 이 매개변수는 아래와 같이 여러 `CREATE INDEX` 또는 `VACUUM` 호출을 실행하기 전에 단일 세션에 대해 교대로 늘릴 수 있습니다.

> ``` sql
> SET maintenance_work_mem TO '128MB';
> VACUUM ANALYZE;
> SET maintenance_work_mem TO '16MB';
> ```
>
> *기본값*: 16MB
>
> *권장값*: 128MB

## wal_buffers

WAL(미리 쓰기 로그) 데이터에 사용되는 메모리 양을 설정합니다. 미리 쓰기 로그는 데이터 무결성을 보장하기 위한 고성능 메커니즘을 제공합니다. 각 변경 명령 ​​중에 변경 내용이 먼저 WAL 파일에 기록되고 디스크에 플러시됩니다. WAL 파일이 플러시된 후에만 변경 사항이 데이터 파일 자체에 기록됩니다. 이를 통해 데이터 파일을 최적의 비동기식 방식으로 디스크에 기록할 수 있으며 충돌 발생 시 모든 데이터 변경 사항을 WAL에서 복구할 수 있습니다.

이 버퍼의 크기는 단일 일반 트랜잭션에 대한 WAL 데이터를 보유할 수 있을 만큼만 크면 됩니다. 대부분의 데이터에는 기본값이 충분하지만 지리공간 데이터는 훨씬 더 큰 경향이 있습니다. 따라서 이 매개변수의 크기를 늘리는 것이 좋습니다.

> *기본값*: 64kB
>
> *권장값*: 1MB

## checkpoint_segments

이 값은 자동 WAL 체크포인트 사이에 채워질 수 있는 최대 로그 파일 세그먼트 수(일반적으로 16MB)를 설정합니다. WAL 체크포인트는 데이터 파일이 체크포인트 이전의 모든 정보로 업데이트되었음을 ​​보장하는 WAL 트랜잭션 시퀀스의 지점입니다. 이때 모든 더티 데이터 페이지는 디스크로 플러시되고 체크포인트 기록이 로그 파일에 기록됩니다. 이를 통해 충돌 복구 프로세스는 최신 체크포인트 레코드를 찾고 다음 로그 세그먼트를 모두 적용하여 데이터 복구를 완료할 수 있습니다.

체크포인트 프로세스에서는 더티 데이터 페이지를 모두 디스크로 플러시해야 하므로 상당한 I/O 로드가 생성됩니다. 위와 동일한 주장이 적용됩니다. 지리공간 데이터는 비지리공간 최적화의 균형을 깨뜨릴 만큼 큽니다. 이 값을 늘리면 과도한 체크포인트가 방지되지만 충돌이 발생할 경우 서버가 더 느리게 다시 시작될 수 있습니다.

> *기본값*: 3
>
> *권장 값*: 6

## random_page_cost

이는 디스크에서 임의 페이지에 액세스하는 비용을 나타내는 단위 없는 값입니다. 이 값은 순차 페이지 액세스 및 CPU 작업 비용을 포함한 여러 다른 비용 매개변수와 관련이 있습니다. 이 값에 대한 마법의 총알은 없지만 기본값은 일반적으로 회전 미디어에서 실행되는 데이터베이스에 대해 보수적입니다. SSD의 랜덤 액세스 비용은 더욱 낮게 설정되어야 합니다.

이 값은 `SET random_page_cost TO 2.0` 명령을 사용하여 세션별로 설정할 수 있으며, 이는 쿼리 계획에 미치는 영향을 테스트하는 데 유용할 수 있습니다.

> *기본값*: 4.0
>
> *권장 값*: 회전 미디어의 경우 2.0, SSD의 경우 1.0

## seq_page_cost

순차 페이지 액세스 비용을 제어하는 매개변수입니다. 이 값은 일반적으로 조정이 필요하지 않지만 이 값과 `random_page_cost`의 차이는 쿼리 플래너의 선택에 큰 영향을 미칩니다. 이 값은 세션별로 설정할 수도 있습니다.

> *기본값*: 1.0
>
> *권장값*: 1.0

## 구성 다시 로드

변경 사항을 적용한 후 변경 사항을 저장하고 구성을 다시 로드하십시오. 가장 쉬운 방법은 PostgreSQL 서비스를 다시 시작하는 것입니다.

- pgAdmin에서 **PostGIS(localhost:5432)** 서버를 마우스 오른쪽 버튼으로 클릭하고 *연결 끊기*를 선택합니다.
- Windows 서비스(`services.msc`)에서 **PostgreSQL**를 마우스 오른쪽 버튼으로 클릭하고 *다시 시작*을 선택합니다.
- pgAdmin으로 돌아가서 서버를 다시 클릭하고 *연결 끊기*를 선택합니다.
